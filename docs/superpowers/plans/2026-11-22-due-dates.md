# Due Dates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any task can carry an optional due date, set from a small calendar on its row, shown as a label that speaks up when the task is due today or late, and readable and settable by Claude and Codex.

**Architecture:** The date is a plain day string on the task (`due: "YYYY-MM-DD" | null`), validated in the shared model, which also owns the pure date helpers (label, month grid). The MCP tools pass it through. The renderer adds a calendar popover (built on the existing `popover.js`) and a date label on each row; both read "today" from one place in `app.js`, the same clock the header uses.

**Tech Stack:** Electron 44, vanilla JS ES modules, no runtime dependencies, `node:test` unit tests, the e2e harness `tools/e2e/main.mjs`, the screenshot harness `tools/shots/main.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-22-due-dates-design.md`

## Global Constraints

- No runtime dependencies; vanilla JS ES modules.
- Every colour comes from `src/renderer/theme.css` variables, except the late pill's `#FBF8EE`, which the spec fixes for both modes.
- Works in Light and Dark, at every Preferences → Text size, and in the compact (narrow) layout.
- A task with no date looks exactly as it does today until the pointer is over its row.
- Copy is fixed by the spec: "Today", "Tomorrow", "Yesterday", short weekday names ("Fri"), dates as "4 Dec" / "3 Jan 2027", "In a week", "Remove date", "Set due date…", "Change due date…".
- Work happens in an AgentGrid worktree on branch `clearday-0.13` (created with `create_worktree`, never `git worktree add`). Commit the spec and this plan there first.

## Review Focus

1. **Daylight-saving and time zones**: a due date must never move by a day. All day arithmetic is on day strings in UTC; `dayString` reads the local date. Pinned in Task 1.
2. **Dates that don't exist**: `2026-02-29`, `2026-13-01` and `"Friday"` are rejected; `2028-02-29` is accepted. Pinned in Task 1 (model) and Task 2 (MCP error text).
3. **Crossing a month or year in the calendar**: arrow keys past the 30th go into December, and the header follows. Next from December shows "January 2027". Pinned in Task 3.
4. **A long task in a narrow window with a date and a bookmark**: the text shortens with an ellipsis, the label stays on one line, and ≡ stays inside the row. Pinned in Task 4.
5. **Claude sending an empty or odd `due`**: `due: ""` on update is an error naming the format, not a silent clear. Pinned in Task 2.

**Interfaces:**
- Produces, all exported from `src/shared/model.mjs`:
